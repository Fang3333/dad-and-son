# 三傻大赛 · 三人分工与 14 天执行表

项目：**时光胶囊 —— AI 平行人生模拟器**（Multiverse Life Simulator）

> 现实情况：三个人都是课堂水平编程，只剩 14 天。
> 所以方案是：**零依赖、无后端、无 API key、双击 index.html 就能玩**。
> "AI 感"靠规则表 + 随机事件 + 文案实现，答辩时说清楚「情景推演，不是预测」即可，这是原方案自己写的定位。

---

## 一、怎么运行

双击 `index.html` —— 完事。不用装任何东西，不用联网。

入口先自己选大学层次（专科 / 985），再选该层次下的两难问题卡；首页还支持「自己写问题」：没有合适的问题卡时，写下你的两难问题，系统在当前层次的剧本里按关键词匹配最接近的模板推演，结果页会标明匹配到哪个模板。

要发给别人：把整个 `三傻大赛` 文件夹压缩发过去，对方解压后双击 `index.html`。

> 三个文件的关系：`index.html`（长什么样） + `data.js`（演什么剧本） + `engine.js`（怎么算）。
> 三个文件各由一个人负责，**不要两个人同时改同一个文件**。

---

## 二、分工（一人一个文件，边界清晰）

### 内容组（建议兼 PM）—— 只改 `data.js`

**你负责"这个项目演什么"。不需要写逻辑，只改文字和数字。**

- `product`：产品名、slogan、免责声明。
- `version` / `changelog`：当前版本号与更新日志（见第七节，**每次更新必改**）。
- `attributes` / `start`：三条属性条的名字、颜色、初始值。
- `stages`：六段大学时光的名字（入学 / 大一 / 大二 / 大三 / 毕业时 / 五年后）。
- `settings.tiers`：入口层次选项（专科 / 985），顺序别改。
- `events`：随机事件池（已写 16 个大学时期际遇，每局抽 2 个落在不同阶段；这是"可玩性"的主要来源，多多益善）。
- `scenes`：**核心剧本**。每个场景 = 一个大学入口问题 + 两条路线 + 每路线 6 个节点 + 2 个结局；`tier` 标明属于哪个层次，`mod` 是成功率修正（专科 +4 / 985 -2）。

**怎么加一个场景**：复制 `scenes` 里最后那一整块 `{ ... }`，粘贴到 `]` 前面，改文字。注意：
- 引号用英文的 `"`，不要用中文的 `“ ”`
- 每个 `{}` 后面要有逗号，最后一个不用
- `tier` 必填 `"专科"` 或 `"985"`；`mod` 照抄同层次剧本的数值
- 每条路线必须写满 6 个节点，和 `stages` 一一对应
- `delta` 里 `skill/wealth/mood` 增减数字，例如 `{ skill:8, wealth:-2, mood:0 }`
- `type` 只能填 `best / positive / challenge / decision`
- `match` 可选，例如 `{ "学术":"A", "实践":"B" }`：兴趣偏向命中哪条路，哪条成功率 +5

**每天验收**：每个层次保持 2 个以上场景，每个场景的两条路线要有明显反差；事件池继续加。

### 呈现组 —— 只改 `index.html`

**你负责"好不好看"。主要改文件开头 `:root` 里的颜色变量。**

- `--bg` 背景色、`--accent` 主色、`--accent2` 高亮色。
- `--radius` 圆角、`--card` 卡片色。
- 想改按钮文字/布局，找 `.btn`、`.hero`、`.branch` 这几个位置。
- 想加背景图案，在 `body` 的 `background` 里加，别动 `<script>` 那两行。

**每天验收**：截图发群里，三个人投票选配色。做出 1 页能拿去答辩的展示图。

### 技术组 —— 只改 `engine.js`

**你负责"怎么算"。已写好的版本能跑，你只改三个地方：**

1. `adjustRate()` —— 设置如何影响成功率（那几行 `+5`、`+2`）。
2. `calcScore()` —— 三种目标各自的评分权重。
3. `makeEvent()` —— 随机事件怎么抽。

**先别动的地方**：`renderTree()`、`drawLines()`、导出相关的函数。等跑通了再加功能。

**每天验收**：能生成两条路线 → 点「在这里改决定」能多出一条分支（上限 6 条）→「随机人生」能掷出新分支 → 导出 JSON 和图片都能用。

## 三、必须三个人一起拍板的事（今天就定）

1. **比赛交什么**：网页演示？PPT？视频？——如果只交 PPT，技术组就不用写代码了，三个人全做剧本。
2. **用哪个场景当主演示**：建议用 `j1`（985 冲保研 vs 直奔就业），评委一看就懂；专科线用 `z1`（专升本 vs 顶岗实习）做对照演示。
3. **主讲人是谁**：答辩只能一个人讲，另外两个人负责演示操作和答问。
4. **免责声明要不要保留**：**强烈建议保留**。原方案自己写了"结果是情景推演，不是对真实未来的预测"，评委问"这靠谱吗"时这就是标准答案。

## 五、答辩时怎么讲（一句话版本）

> "我们做了一个能探索人生选择的交互模拟器。用户先选大学层次（专科 / 985），再从大学入学的一个两难选择出发，系统按规则生成两条发展路线、推演六段时光直到五年后，还能改任意一个决定、看后面怎么变。
> **它不是预测未来，而是帮人把选择看得更清楚。** 技术上不需要大模型 API，规则系统就能跑，所以完全离线可用。"

评委问"创新在哪"：
1. 交互式选择模拟，不是静态的职业规划问卷；
2. 可以改决定、生成平行分支，看"如果当初"；
3. 有随机事件，同一问题每次玩结果都不同。

评委问"AI 在哪"：坦诚说规则驱动的情景生成，AI 部分是可插拔的（未来接大模型只需替换 `engine.js` 里的 `adjustRate` 和文案生成）。**不要硬吹**，被问穿更扣分。

## 六、常见翻车点

- 中文引号 `“ ”` 写进 `data.js` → 网页直接白屏。用英文 `"`。
- 少写逗号 / 多写逗号 → 白屏。改完 `data.js` 立刻刷新看一眼。
- 三个人同时改一个文件 → 互相覆盖。一人一文件，铁律。
- D8 之后还想加新场景 → 不加，会拖垮彩排。
- 用 `file://` 打开时如果浏览器拦了脚本 → 换 Edge/Chrome，或右键允许本地脚本。

## 七、版本与更新日志（每次更新必做）

当前版本：**3.0.0**。版本号遵循 semver：

- 玩法/结构大改版 → 主版本 +1（如 2.0.0）
- 新剧本、新功能、新事件包 → 次版本 +1（如 1.1.0）
- 文案、数值微调、修 bug → 修订号 +1（如 1.0.1）

**每次更新，两个地方一起改（都在内容组的 `data.js` 职责内）：**

1. `data.js` 顶部：`version` 改成新版本号；`changelog` 数组**最前面**追加一条：
   ```js
   { version: "1.0.1", date: "2026-11-18", tag: "修复",
     items: ["修了什么，一句一条", "改了什么，用户能感知的话"] },
   ```
   `tag` 只能填：`首发 / 新增 / 优化 / 修复 / 变更`。
2. 仓库根目录 `CHANGELOG.md`：在顶部按同样内容加一节 `## [1.0.1] - 2026-11-18`。

改完后：顶栏版本号会自动显示新版本（引擎读 `DATA.version`），点版本号就能打开应用内更新日志面板，导出的 JSON / PNG 也会带上新版本号。
